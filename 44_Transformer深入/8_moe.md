# 8. MoE混合专家

## Dense模型的困境

提高能力 → 加宽加深 → 每个token的计算和显存同步增长。
MoE的目标：**容量大但计算省**。

2026年初的新架构里，7成以上是某种形式的MoE，dense模型已成少数派。

## 核心思想

把Transformer Block里的FFN换成一组"专家"FFN + 一个路由器：

```
token → router打分 → 选Top-K个专家 → 加权合并输出
                ↘ 共享专家（每个token必经）
```

- 总参数量 = 容量（知识多）
- 每token激活参数 = 计算量（便宜）

两者解耦，是MoE的本质。

## DeepSeekMoE的三个关键设计

| 设计 | 说明 |
|------|------|
| 细粒度专家 | 专家多而小（V3: 256选8），专业化程度更高 |
| 共享专家 | 每token必经，学通用知识，避免公共模式在每个专家里重复学 |
| 负载均衡 | 防止router坍缩到少数专家 |

## 负载均衡

Router是可学习的，训练初期容易"坍缩"：少数专家被选爆，其余闲置。

经典方案（Switch Transformer）——辅助loss：

```
L_balance = E × Σ f_i · P_i    (f_i: 专家i被选频率, P_i: 平均路由概率)
均匀路由时 ≈ 1，坍缩时显著变大 → 加进总loss一起优化
```

DeepSeek-V3改用免loss方案：给每个专家的打分加动态bias，负载低了就调高，
不干扰主梯度（auxiliary-loss-free）。

## 真实模型对比

| 模型 | 总参数 | 激活参数 | 激活比 |
|------|--------|---------|--------|
| LLaMA 3 70B (dense) | 70B | 70B | 100% |
| Mixtral 8x7B | 47B | 13B | 28% |
| Qwen3-235B-A22B | 235B | 22B | 9% |
| gpt-oss-120b | 117B | 5B | 4% |
| DeepSeek-V3 | 671B | 37B | 6% |

DeepSeek-V3用37B激活参数达到旗舰水平，训练成本约$6M——2025年初开源格局被改变的原因。

## 代价

- **显存**：推理要装下全部参数（671B模型即使只激活37B，也要多卡才放得下）
- **训练**：负载均衡、专家并行（EP）、all-to-all通信都是工程难题
- **计算不规则**：每个token路径不同，batch内要按专家分组（grouped GEMM）
